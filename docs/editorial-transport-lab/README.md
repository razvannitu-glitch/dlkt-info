# Editorial Intelligence 05A — isolated transactional persistence laboratory

NO-GO for production. This PostgreSQL 17 schema is restricted to the disposable database named editorial_transport_test. All roles, passwords, digests and vectors are synthetic test fixtures. It is outside canonical source and automatic migrations. Never run this script on a hosted or application database.

The previous single-process reference is insufficient for independent workers. This laboratory models one bounded UTC-day window and an authoritative database clock. Every operation locks the same singleton row until transaction commit, deliberately favoring correctness over throughput. A non-login owner defines fixed-search-path functions. Separate authenticated fixture roles may issue, write/withdraw, inspect or sweep, without table privileges. A grant digest is a bearer-like internal lookup key; it is not proof of real consent. The fixture issuer is trusted only in the laboratory. The database validates fixed scope/version/taxonomy/coverage, exact integer vector length/order and total bound again. It stores one reversible vector per grant, not article/user/account/audience identifiers. Exact vector replay is idempotent after validation, conflicting replay fails, and expiry/withdrawal removes the vector. UTC-day closure, clock rollback and capacity are explicit holds/boundaries. Closed digest tombstones and lifetime counters remain bounded until the entire disposable database is destroyed.

This is a pending-data transaction experiment, not a daily report, production schema, privacy certification, hosted rate limit, anonymous aggregation or consent coordinator. The inspector mutates expiry maintenance and exposes synthetic pending sums only. No actual user consent, raw browser events, real article identities or application service credentials enter the database. No integration with Supabase, public APIs, admin, ranking or billing exists. A separately reviewed adapter must bind the actual canonical byte parser to fixed SQL parameters and authenticate distinct real roles; cross-tab/server consent fencing, privacy and retention decisions, real shared abuse admission, contributor suppression, recovery and hosted concurrency/performance must still be verified. No sealed aggregate is produced. Do not label pending sums or missing data as validated daily metrics.

CI uses a fresh PostgreSQL 17 service, actual SCRAM fixture login roles and independent psql connections. The dedicated tests check role isolation, expiry, invalid vectors, immutable replay, rollback, simultaneous writes, lock-waiting withdrawal, and the final admission race. These are candidate assertions until exact-head CI succeeds. The existing production-related release tests also remain required. No additional application dependency or hosted infrastructure is provisioned.
