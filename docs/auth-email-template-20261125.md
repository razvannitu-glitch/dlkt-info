## Language transport

The account page uses the existing resolved interface language, after bounded initialization of the anonymous approximate country hint. A manual language choice wins; the country hint never saves a city or changes a profile. The exact `?returnTo=wallet` intent remains unchanged by the account picker.

The server constructs the fixed first-party URL `https://www.dlkt.ee/account?lang=<catalog-code>` from the supported locale resolver, then sends it in the Supabase Auth OTP `redirect_to` parameter. There is no caller-controlled hostname/path. The hosted template uses exact `.RedirectTo` comparisons for the 30 shipped codes. It does not use `.Data.locale`, because stored metadata is not evidence of the current choice for an existing account. English is the fallback for an absent or unrecognized redirect.

Before saving templates, verify the project's Site URL/redirect allowlist admits these exact fixed URLs. Supabase Auth can replace a rejected redirect with Site URL, which would intentionally select the English fallback. Prefer the existing matching production Site URL; if exact allowlist entries are needed, add only the 30 catalog URLs and preserve other existing entries. Read the settings back. Do not infer this hosted condition from a passing transport mock.
