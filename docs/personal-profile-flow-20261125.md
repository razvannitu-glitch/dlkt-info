A2. Validate versioned private preferences, reuse the existing wallet profile namespace and owner/revision-bound store; read legacy profiles compatibly without inferring city or needs. Exact key, dense array, duplicates and unknown values fail closed. Do not put preferences into public URLs, caches, logs, external source requests or analytics.
A3. Personal local selection evaluates all validated available candidates before preferences/pagination. Preserve kind-specific time, geography and source gates; expose actual available coverage and expiry, and distinguish unconfigured, unavailable/expired and no matches without inferring service health.
A4. National/international information remains eligible via explicit existing interests. Personal reasons must distinguish declared-interest relevance from confirmed local applicability. No unsupported household impact or inferred medical, financial or family state.
A5. Save/load/update/delete/conflict/session-expiry behavior must be explicit and verified; no failed write is shown as saved. Sign-out or account change removes in-memory personal results and old account responses cannot repaint them.

A7. Verify strict TypeScript, meaningful unit/API/database tests and existing release gates; test authenticated browser journeys with two isolated controlled identities and session restoration. Controlled identity evidence must never be described as live OTP or hosted-runtime proof.

No email/OTP sending to real people, credentials disclosure, paid checkout, external messages or new services in this lot. If live authentication evidence is unavailable, preserve the complete verified implementation and explicitly identify the remaining activation gate.
