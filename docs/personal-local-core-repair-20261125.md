## Acceptance before generation

P1. The versioned profile accepts only its own exact version, cityId and dense supported needs fields. Unknown, inherited, extra or duplicate values fail closed. Returned preferences are detached and immutable.

P2. A local match requires the confirmed city and an explicitly chosen need. It keeps the original validated source card and explains confirmed-city-and-declared-need with city-context-only applicability. A city-wide notice never becomes a household impact claim.

P3. Selection preserves the existing source identity, geography, freshness, expiry and kind-specific temporal checks. A forecast for the next complete hour remains valid; stale, future-checked, tampered and wrong-city snapshots cannot create matches.

P4. Empty needs do not infer preferences. Selection does not mutate its inputs. Meaningful fixtures exercise successful selection as well as the negative boundaries.

P5. This component remains unused by public reader, account, wallet and billing routes. No private persistence, entitlement, new source, infrastructure, dependency, CSS or notification activation belongs to this repair.

P6. Strict TypeScript, the existing complete application/packaging/release checks and independent raw-source review must pass before calling the component verified. Generated manifest and source pin must come from the existing bounded generator and be checked against their exact input commit and every digest.
