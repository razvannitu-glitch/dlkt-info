The disposable PostgreSQL 17 experiment uses synthetic lab identities and example.invalid URLs only. No probe, network reads, real approval, editorial or reader code, production migration, cron, secrets, or data. It evaluates transactional serialization, durable start and terminal result records, idempotent retry, abandoned attempts, contiguous history and role boundaries. The non-login owner is trusted; a database superuser is outside this threat model. The isolated CI database is discarded after the job.

The worker starts a candidate attempt transaction and may probe only after receiving a committed created result. Exact retries return replay-open/replay-terminal; a lost start response cannot authorize duplicate reads. Different pending requests return busy. Finish records one terminal outcome; matching replay is idempotent and conflicting replay fails. A separate reaper can close a five-minute-old start as abandoned. No direct table writes, no arbitrary URLs or raw document bodies. The private reader retrieves every attempt in sequence under a candidate lock, including incomplete and failed outcomes. The 256-attempt cap is deliberately conservative, with no deletion or compaction; reaching the cap holds further starts. A reviewed baseline/archival strategy is still required.

Observed metadata is only a bounded five-fingerprint projection, evidence digest and timestamp; its shape and canonical SHA-256 binding are checked, not the authenticity of source observations. No runtime adapter or authoritative independent review store exists yet, no semantic/rights/translation validation, no planner integration and no ability to grant publication. All read results explicitly carry activationAllowed=false. Do not infer editorial reusability from a complete storage prefix. Any unresolved failure or gap holds the snapshot. Next increment must bind the actual controlled probe, validate canonical exact receipts, persist separate scope-specific reviews, test history-to-planner integration, and obtain independent review; actual rollout requires the gates in #93.

Run only in disposable CI using the dedicated branch workflow. Pending CI is not evidence that the implementation passes. No changes to canonical source or assets.

Temporal hardening: the five-minute lab deadline fences worker completion even before the reaper runs; overdue unresolved starts remain visible as expired-open and cannot be bypassed by another start. Exact terminal replay remains idempotent. Future timestamps relative to the locked read's database clock, tied/overlapping adjacent attempts, and missing sequence produce integrity-held. A zero-attempt prefix is empty, not complete. These are storage guards, not independent reviews. The deadline is a laboratory engineering choice, not a production SLA.

Evidence binding: the private PostgreSQL verifier reproduces the existing dlkt-knowledge-observation-v1 compact JSON hash format for restricted synthetic identities, URLs and ordered five-fingerprint projections. It uses UTC millisecond precision and rejects an invalid or mismatched digest before recording a successful observation. Locked readback recomputes positive bindings and holds corrupted history. An independently computed static interoperability vector and negative binding, precision, privilege and tampering regressions exercise this contract. The digest is unkeyed: an authorized worker can calculate it for invented fingerprints. No authenticated source receipt, approval, real-probe integration, or production-ready trust chain is implied.
