## Committed transaction adapter experiment

A strict TypeScript adapter orchestrates a committed start, controlled observer, separate attestation, terminal persistence and exact locked readback. A lost start reply cannot trigger a source read; a lost attestation reply cannot trigger finalization; an uncertain terminal write is reported recorded only if readback proves the exact terminal result. Open, held, failed and ambiguous attempts are never approval. The adapter allows positive controlled synthetic lab fixtures only; the fixed historical NSW lab identity can exercise controlled held results, not positive admission. No real candidate admission digest is accepted. A dedicated disposable PostgreSQL 17 job uses three independent login identities, SCRAM loopback authentication, fixed test-only credentials and separate grants, with no superuser role in the adapter's calls. The tests exercise wrong credentials, cross-role denial, commit visibility, replay, ambiguous acknowledgement, missing coverage and exact readback. The existing source and claim evaluators run with controlled HTML and a fixed test transport; no actual publisher requests, no historical evidence retimestamping. These are laboratory transaction semantics, not an authenticated external source or production connection. Production service identity, real observer transport, persistent scoped review, integration with the existing advisory planner, bounded retention, and independent review remain separate gates.

The canonical NSW lab subject is also held-only at the SQL boundary: both attestation and positive finalization reject non-synthetic subjects, and readback treats any such stored positive/attestation as an integrity hold. The integration case exercises both rejections before running the controlled missing-coverage observer.
