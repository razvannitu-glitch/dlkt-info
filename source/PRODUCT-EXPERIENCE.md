# One identified story per reading card — 22 November 2026

A publication event or identifiable subject thread occupies one top-level reading card. Reports from additional publishers, repeated headlines, follow-up stages and newly checked coverage belong inside that card with each original title, publisher, date, link, attribution and stored identity intact. The rule applies before the daily budget, continuation, Explore sections, personal topic selection and saved briefing composition. Broad categories, countries, publishers or shared entities alone do not establish that two events are the same. Unknown relationships remain separate rather than suppressing unrelated information.

Thread grouping is deterministic and shared across these reading surfaces; explicit named or numbered events retain a stable thread key across representative changes. Matching is conservative and does not claim perfect universal semantic or multilingual detection. Contradictory reports remain individually attributed; multiple reports never imply independent confirmation or editorial consensus. Freshness, rights, conflict quarantine and source eligibility are evaluated before originals enter a group.

Followed categories count an identified story once across categories. An additional publisher on an already known thread is additional coverage, not a new event; an actual correction remains attributed to the changed original. All comparison originals and explicit acknowledgement boundaries are retained. Automatic refresh neither acknowledges changes nor writes memory. Saved source articles remain individual original records with their existing bookmark IDs and links. Their collection groups identified publication threads for display before the budget, while each saved original can still be opened, compared and removed separately. The archive is not promoted into current source evidence, and conflicting saved copies are retained rather than silently discarded.

The related-coverage disclosure and its return label have explicit copy in every shipped interface locale. Original publisher wording retains its own language. No theme, stylesheet, translation provider or paid processing is introduced for this rule.

# Public reader: useful context and followed categories — 22 November 2026

The current public reader is served at `/`. Publication cards retain their complete original title, admitted publisher excerpt, date and source link. New compact provenance labels identify the reviewed edition language, publisher country and supported publisher country tags or scope. They never infer an event location or a personal consequence from the publisher country. Excerpts remain original attributed wording, not a generated summary. Unknown provenance is omitted. Ordinary news discovery remains headline/date/link only under its existing source policy.

Follow on a card refers to the exact displayed editorial category. The 20 category IDs remain distinct from legacy topic settings. Following remembers that category and, when source checks are usable, its initial comparison baseline in the existing reader IndexedDB meta store. It does not change the saved briefing, home city, theme, reading language, saved cards or the existing Changes checkpoint. It is not part of account import/restore or reading exports.

The homepage shows followed-topic changes against those explicit checks, with new-to-comparison and updated-listing counts, links to public cards and separate partial, expired, unavailable and no-baseline states. A fresh baseline is saved only by following or explicitly choosing Save current check. Reloads and timer expiry never acknowledge changes. Stop following removes one category; the existing clear-reader action removes all follows. Cross-tab revision checks prevent silent overwrites, and transaction errors cannot claim persistence. Comparisons reuse the current public snapshot and existing freshness policy; this feature adds no source requests, polling service or closed-page monitoring.

When the public ingestion engine excludes conflicting identities, following can compare the remaining reconciled catalog after validating the complete retained dataset. The original global exclusion count is recorded with each explicit baseline. A comparison stays partial while either that baseline or the current snapshot contains exclusions, and the interface explains the global limitation without attributing it to an individual category or publisher. Source health, errors and freshness checks remain unchanged. Unavailable or expired checks cannot become usable through this adapter. Only an explicit new check on a clean catalog clears a saved exclusion count; the existing Changes checkpoint continues to reject raw conflicted snapshots.

All new actions, errors, return states and provenance labels are supplied in all 30 interface locales, including the four RTL interfaces. Original publisher wording retains its language and direction separately from localized interface text. Automatic article translation is not enabled: the current project has no configured model/translation provider or article-translation integration. No new provider, dependency, paid processing or source-republication permission is introduced by this release.

The source classifier now distinguishes unsupported figurative weather descriptors from literal forecasts and hazards, and child-protection or sectoral summits from diplomatic events. The same corrections apply to newly acquired and already stored cards without changing their titles, hashes or source identities. The versioned classifier forces explicit replacement of an incompatible follow baseline rather than inventing a change count.

# DLKT Info 0.8.8 — Exact Companion Handoff

DLKT Info is a finite personal information companion. It does not transfer an infinite feed to the user and does not hide selection, evidence or follow-up rules.

The normal entry begins at `/start`. The user selects topics, exact entities, evidence policy, local delivery time and a positive finite card budget. There is no fixed commercial ceiling of eight entities or twelve cards. Entity configuration is payload-bounded for security; the briefing size is user-defined.

The same visible contract opens immediately in `/companion`. Email OTP is required only when the user chooses cross-device persistence. After verification, the server saves the exact contract atomically and the Companion restores it automatically on another authenticated device. An explicit valid URL always takes precedence over stored preferences.

Trust filtering happens before ranking. Explainable Memory shows every bounded influence. Actions change attention, never truth. Delivery rules change only the return path. Contradictions remain visible and no engine selects factual truth automatically.

A zero-card result is valid. Stable information is not repeated merely to fill the interface. Real acquisition, delivery workers, public cards and commercial release remain behind independent runtime gates.
