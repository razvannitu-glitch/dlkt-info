# DLKT Control
Read-only, private server-rendered overview at /admin. No collection script, cookie, database migration, payment change or public-reader UI change.

Disabled by default. To enable after review, configure DLKT_INFO_ADMIN_ENABLED=1 and DLKT_INFO_ADMIN_USER_IDS with verified immutable Supabase Auth UUIDs (comma-separated, maximum 20). Existing account bridge, verified persistence and session authentication must be operational. Never set admin IDs from editable user metadata. Keep all secrets server-side. Existing Supabase secret is used only for HEAD aggregate counts of reader profiles, not individual records. Profiles are not the same metric as Auth users.

Optional audience reads use the documented Vercel Web Analytics visits/count and visits/aggregate endpoints. Keep DLKT_INFO_ANALYTICS_READ_ENABLED disabled until measurement, disclosure, retention, cost and credential scope have been reviewed. Configure DLKT_INFO_ANALYTICS_VERCEL_TOKEN (minimum available permissions, server-side only) and DLKT_INFO_ANALYTICS_SINCE (actual activation instant, ISO UTC). Queries are fixed to the DLKT INFO production project. No historical data is invented; provider retention and visitor definitions apply. Recent visitors means visitors during the last 30 minutes, not live concurrent users. Country, referrer, path and device are provider-reported; city, session, return frequency, card events and revenue require a separately verified measurement design. No new provider or paid feature is activated by this change.

Run existing release verification and public package tests before merging. Validate authorized, unauthenticated and unauthorized accounts against an isolated preview before enabling production. Do not copy production secrets into a preview. Remove the enable flag to disable access immediately. Use no-store responses; do not cache private dashboard output.
